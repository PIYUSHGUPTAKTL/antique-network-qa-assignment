API session-client correction

The first Java attempt against the authenticated patched bank failed fixture setup: REST login returned 200, but own-account reads returned 401. BankClient.form replaced all saved cookies with only the latest response cookies; a successful registration response did not re-send Set-Cookie. The client now retains existing cookies and merges any rotated response cookies. No ownership assertion was weakened. The failed setup/skip results remain under diagnostics/initial-api; the table above records the complete run after correction. Live integration controls verify that legitimate authenticated operations succeed and foreign operations remain denied.

Namespace-aware parity correction

Once the live schema passed, jsonXmlParity exposed a framework bug: XML normalization used prefixed tag names as collection/field names. A qualified empty transactions element became a string instead of a list, and qualified numeric fields kept their prefixes and string values. Two new regression tests failed before the change (parity-regression-red.log). Normalization now uses DOM local names while retaining exact decimal comparison, canonical record IDs, missing-field checks and secure XML parsing. Live namespace/schema validation remains a separate unchanged assertion. The intermediate failure matrix remains in diagnostics/parity-intermediate-api.

Review findings and intermediate verification

Independent review confirmed that raw numeric-only path matching missed signed and percent-encoded IDs, SOAP metadata GET was parsed as an empty body, and optional REST/SOAP calls lacked outbound identity. These were corrected: URI decoding precedes integer ownership checks, WSDL metadata is accessible, and credentials propagate only to the same loopback application/port. Regression checks exercise those routes and legitimate controls.

The first compiled patch used an SQL predicate HSQLDB could not type-infer; a focused deposit failed with SQLSyntaxErrorException. The predicate now includes the sufficient-funds clause only for debits, comparing the column with a positive typed amount. Subsequent build/deployment logs and live regression evidence are retained. Intermediate failures are diagnostics, not counted as passing final tests.

An intermediate Java matrix after the cookie fix passed 14/15 API cases per seed. Root-only XML qualification left JAXB types in a different schema namespace; unchanged live-XSD validation detected the unresolved account type. The final package-level namespace aligns domain roots and types while preserving unqualified child fields. That intermediate matrix is retained in diagnostics/schema-intermediate-api.

Coverage limits and reproducibility

The loanRules method contains eight boundaries for a 100-unit loan and 20% local threshold: down payments 0.00,19.90,20.00,30.00,9999.00 and available funds 19.90,20.00,30.00. Settings restore in finally. The reset method deliberately removes local data, verifies fixture-loss classification, and initializes the bank in finally.

The 46-case risk plan is broader than automated coverage. No full upstream ParaBank unit/IT suite was executed; some upstream tests explicitly expect overdrafts and conflict with this approved local policy. The compiled overlay, assignment suites and real boundary regressions define the verified scope.

Local optional RESTJSON/RESTXML/SOAP own-account controls passed in the boundary probe; arbitrary remote endpoints were not certified. Credentials are not forwarded to arbitrary hosts. Administrative/reset endpoints remain available in this loopback-only demo. This is not a production security audit or deployment.

Native OpenCart percentage option pricing and customer-facing voucher remaining balance remain unavailable. A fixed reduction fixture and minimal QA Spanish labels are used. Categories/options/currencies/category associations use owned SQL; full admin-UI-only fixtures and complete localization certification are not claimed.

No load/stress, accessibility certification, email delivery, real settlement, Docker Grid, hosted CI or native JDK 17 run was performed. Browser CDP/Java deprecation warnings can appear; assertion/process results determine status. No automatic retries were used.

The original submission ZIP and previous reports were preserved. The new fixed submission ZIP excludes secrets, .git, target and caches. Synthetic bank data remains locally because per-customer deletion is unavailable. Application recreation resets ephemeral local data.

Top-level Surefire TEST*.xml determines counts; duplicate JUnit exports and lowercase testng-results.xml are excluded. results.json and test-case-results.csv contain final case details. Diagnostics remain separate and visible. Raw_Run_Evidence.zip includes metadata, probes, logs, HTML/XML reports and Allure attachments.
